# Matching 921600-baud RLR141 transport experiment

Software scope: STM32 USART3 / ESP32-S3 UART1 only, plus queue service and loss
reporting. STM32 USART1 remains115200,8N1. No dsPIC/ALR firmware, radio clock,
PHY, plan EC2B4B2A/revision1, IDs, antenna calibration, RF scheduler, sparse AR
operations or UWB wire fields are changed. All hardware operations are manual.

## Findings from the supplied recording and code

`/tmp/rlr141-stream-check.jsonl` contains343006 application bytes over29.981906s:
11440.433B/s,303 TDoA vectors,909/909 valid components,119 AR results,160 clock
and515 raw multi-RX records, with no DATA2. Its stream ACK and source sample
status confirm acquisition was active. This is99.31% of requested115200/10
capacity before additional DATA2. It cannot sustain the proposed combined load.

There are also two confirmed software service defects:

* STM32 had an independent UWB pending slot which always outranked the generic
  LOG/DATA FIFO. Continuous pending UWB could indefinitely defer DATA2 and fill
  that FIFO. The old UWB drop statistic did not describe sensor starvation.
* ESP32 classified DATA/LOG as control replies in tcp_out (eight records). It
  parsed a256-byte UART chunk before sending at most one record, then slept one
  RTOS tick. This build uses CONFIG_FREERTOS_HZ=100, so that sleep is10ms. Short
  LOG/reply bursts could fill tcp_out even while a PC could read promptly. This
  is the exact path to tcp_tx_queue_full; the historical incident's particular
  burst/client timing cannot be reconstructed conclusively from the old log.

The fixes address both mechanisms; a baud increase alone is not considered proof.
No diagnostic UWB producer is disabled or rate-limited.

## Implementation and bounds

STM32 uses HAL_UARTEx_ReceiveToIdle_DMA with a2048-byte circular SRAM buffer,
DMA1 Stream1/Channel4 (USART3_RX). This allocation is supported by
[ST RM0090, DMA1 request mapping](https://www.st.com.cn/resource/en/reference_manual/rm0090-stm32f405415-stm32f407417-stm32f427437-and-stm32f429439-advanced-armbased-32bit-mcus-stmicroelectronics.pdf).
The actual F405RGT6 project has no other allocated DMA streams. SPI1 uses
synchronous HAL SPI transfers; USART1 uses byte IT; USB FS DMA is disabled.
ADC DMA requests are disabled. No SPI, RF EXTI, USB or UART1 priority is changed.

MSP initialization configures and links hdmarx, circular byte transfers and
DMA1_Stream1_IRQn. That strong IRQ handler calls HAL_DMA_IRQHandler. USART3's
existing IRQ handles IDLE/errors. HT/IDLE notifications only count events; TC
increments the wrap counter. No callback parses, prints, allocates or waits.

The task snapshots NDTR plus pending TC under a short critical section, accounting
for a completed wrap before its IRQ and avoiding double-counting after the IRQ.
It copies at most128 bytes per task to the existing bounded parser ring, then
consumes the existing128-byte parse budget. Complete DMA laps are not inferred
from modulo positions alone. The2048-byte DMA ring must be serviced regularly:
more than1024 unread bytes fails closed, leaving half-buffer overwrite headroom.
Progress after a>=22ms polling blackout at921600 is treated as ambiguous overflow;
unobservable extra laps cannot be counted exactly. A300us blackout receives
about28 bytes and fits comfortably within the buffer, subject to hardware tests.

DMA batch timestamps conservatively use the previous poll time (or the oldest
remaining batch time), not parsing time. Commands cannot become artificially
fresh after a main-loop pause. Exact per-byte timestamps are unavailable with
this DMA design. UART framing/noise/overrun/DMA errors invalidate the transport,
discard uncertain input through a delimiter, and restart RX in task context.
HAL abort/restart never runs in the application RX callback. Init failures and
restart/error/overflow counters remain visible; a fresh valid session is needed.

USART3 TX remains interrupt-driven. TXE delays insert idle gaps instead of losing
received bytes or corrupting a transmitted byte; at the expected~13kB/s the CPU
has far fewer TX interrupts than the full921600 line rate. DMA TX is not added
without physical evidence of a TX service bottleneck. Queue/byte counters and the
physical campaign must verify achieved throughput and RF coexistence. Host tests
do not establish actual interrupt latency or electrical reliability.

STM32 now has a separate latest DATA2 slot. Control replies retain priority,
then at most three UWB records precede a pending DATA2, then optional LOG FIFO.
A started record is never spliced. Superseded sensor observations are counted;
no cached record is repeatedly published or interpolated. DATA2 format and
source/sequence/age/signed phase counts are unchanged. USB ESP_STATUS reports
sensor_sent, sensor_coalesced and transmitted bytes in addition to UART faults.

ESP32 preserves eight control slots and adds eight separate sensor slots. LOG
uses the existing optional telemetry queue. It services TCP after four completed
UART records and between chunks, drains up to2048 RX bytes per tick and up to16
nonblocking TCP writes /4096 bytes per drain. A control queue at capacity gets a
nonblocking drain attempt before a real backpressure disconnect. All partial
records finish before switching classes. DATA2 receives bounded service after
three queued telemetry lines. Optional loss remains counted; genuine stalled
TCP, control overflow, malformed framing and single-client rejection remain.
UART RX ring size remains2048 bytes. Its driver event queue is64 entries to cover
the ring's32 FIFO-threshold events plus idle/error headroom; up to64 events are
handled per iteration. FIFO threshold64 / timeout2 characters reduce driver
batch latency. No TCP queue size was simply increased to mask the defect.

No PC ARM/heartbeat protocol is reintroduced. M/STOP/MOTOR_STATUS, internal
dsPIC ARM/HB, ACK matching, speed limits, disconnect STOP and no reconnect replay
remain as described in [the robot guide](robot_experiment.md).

## Actual nominal clock dividers and utilization

HSE8MHz, PLL M8/N336/P2 yields168MHz CPU; APB1 divides by4, so USART3 uses42MHz,
not the84MHz APB1 timer clock. Oversampling remains16. The bundled HAL truncates
USARTDIV to hundredths before fractional rounding and produces BRR45 for921600.
The experimental USART3 initialization explicitly corrects this to nearest
integer BRR46, without changing any peripheral clock. Native compile assertions
check the real HAL macros and the corrected divider. Legacy USART3 retains the
original HAL BRR364; USART1's APB2 84MHz/115200 HAL BRR729 is unchanged.

ESP32 explicitly selects its configured40MHz XTAL. The installed IDF6.1
esp_hal_uart/esp32s3 uart_ll sets a fractional divider in sixteenths, floored:
694/16 at921600 and5555/16 at115200. Runtime uart_get_baudrate is logged at startup.

| Requested | STM32 USART3 nominal actual | ESP32 UART1 nominal actual | Endpoint difference |
|---|---:|---:|---:|
|921600 |913043.478 (BRR46, -0.9284%) |922190.202 (+0.0640%) |1.0018% |
|115200 rebuilt pair |115384.615 (BRR364, +0.1603%) |115211.521 (+0.0100%) |-0.1500% |

The preserved pre-upgrade ESP binary used UART_SCLK_DEFAULT/APB80MHz rather
than the new explicit XTAL source: its nominal115200 readback is115201.152
(divider11111/16), with the same STM32 BRR364. Restore that exact pair together.

These exclude crystal tolerance and electrical effects. USB ESP_STATUS reads back
PCLK1/BRR/actual nominal baud rather than assuming the requested rate.

Theoretical921600,8N1 capacity is92160B/s; STM32's nominal divider gives91304B/s
before TX gaps. Observed old traffic11440.433 plus maximum DATA2 1350 yields
12790.433B/s:13.88% of requested capacity /14.01% of STM32 nominal actual capacity,
plus additional control/diagnostic traffic. At115200 the same load exceeds111%.
Use `python3 tools/uart_link_budget.py` in epuck-esp32 to reproduce the math.
Application bytes, UART capacity, Wi-Fi overhead and physical reliability are
separate quantities.

suites and the new DMA suite. That suite checks start failure/retry, fragmented and
concatenated framing, repeated wraps and pending-TC accounting, a masked300us-sized
burst, UART/DMA errors, overwrite recovery, continuous UWB fairness, and300s of
